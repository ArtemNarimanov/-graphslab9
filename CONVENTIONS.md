# CONVENTIONS — правила кода GraphLab

Документ фиксирует стиль, обработку ошибок и запреты для `graphlab_app.py`
(GUI) и `graph.py` (CLI). Архитектурные решения — в `ARCHITECTURE.md`,
пользовательская документация — в `README.md`. Конфликт: этот файл
решает вопросы «как писать», ARCHITECTURE.md — «что и зачем».

---

## 1. Стиль кода

### Общие

- Python 3, кодировка UTF-8; первая строка каждого файла —
  `# -*- coding: utf-8 -*-`.
- Отступ 4 пробела; две пустые строки между топ-уровневыми функциями и
  классами; длина строки ~100 символов.
- Имена: функции и переменные — `snake_case`, классы — `PascalCase`
  (`YLine`, `App`), константы модуля — `UPPER_SNAKE` (`PALETTE`, `F_BODY`,
  `X_FILE`). Приватные имена — с префиксом `_` (`_mark_dirty`,
  `_preview_tabs`).
- Комментарии и docstring — **по-русски**, как и весь интерфейс. Docstring
  у функции — одно-три предложения: что делает, ключевые детали формата,
  контракт возврата (например, `None — была ошибка (уже показана)`).
- Типовые аннотации — на публичных утилитах модульного уровня
  (`def read_numbers(path: str, start_line: int = 1)`); внутри класса
  `App` аннотации можно опускать.
- Форматирование строк — f-strings; никаких `%` и `.format()`.
- Секции файла отделяются заголовками-комментариями:
  `# ---------- построение графиков ----------`.
- Импорты: стандартная библиотека, затем внешние (`matplotlib`, `PIL`,
  `tkinter`). **`matplotlib.use("Agg")` вызывается до импорта pyplot** —
  всегда, в обоих файлах.

### Структура GUI (`graphlab_app.py`)

Один файл, три слоя (см. ARCHITECTURE.md §2): модульный уровень → `YLine` →
`App`. Новые функции размещаются в своей секции рядом с аналогичными:

- виджеты создаются **только через фабрики** `_entry`, `_btn`,
  `_muted_label`, `_card`, `_field_row` — они задают тему и контекстное
  меню (ПКМ). Сырые `tk.Entry/Label/Button` вне фабрик — только для
  специфичных виджетов (кнопка цвета, canvas предпросмотра);
- состояние UI — в `StringVar`/`BooleanVar`, напрямую поля не хранятся;
  каждое пользовательское поле подписано на
  `trace_add("write", lambda *a: app._mark_dirty())`;
- цвета интерфейса — только из словаря `T`, шрифты — из
  `F_BODY/F_SMALL/F_HEAD`. Новые цвета добавляются в `T` с именем роли,
  а не в код;
- раскладка — `grid` внутри карточек; карточки создаются через `_card`.

### CLI (`graph.py`)

- Самодостаточный скрипт: свои копии `read_numbers`, без импорта из
  `graphlab_app.py` (дублирование осознанное, см. §3);
- stdout — только результат (строки `![...](...)` и сводки), предупреждения
  — в stderr (`file=sys.stderr`);
- matplotlib рендерит в PNG через `Agg`, окно не создаётся.

### Документация

- Все .md-документы — на русском; README.md — для пользователя,
  ARCHITECTURE.md — каноническое описание с привязкой к строкам.
- **При изменении структуры** (новые классы/функции/секции, сдвиг строк)
  обновить `ARCHITECTURE.md` в том же коммите — ссылки на строки должны
  оставаться верными.

## 2. Правила обработки ошибок

### Принципы

1. **Ошибку пользовательского действия показываем и возвращаем признак.**
   GUI: `messagebox.showerror("Ошибка", "...")` + возврат `None`/`False`.
   Пример — `_save_current` (`graphlab_app.py:859-870`). Вызывающий код
   проверяет результат и останавливается; диалог показывает тот, кто знает
   контекст.
2. **Предупреждения не фатальны.** Неполные данные (нет X/Y, нет точек,
   разная длина) собираются в список `warnings` (`_prepare`,
   `graphlab_app.py:598-657`) и показываются в статус-строке с префиксом
   `⚠`; строка пропускается, работа продолжается.
3. **Ошибки чтения файлов — по файлу.** Ловим `(OSError, UnicodeDecodeError)`
   вокруг каждого чтения (`graphlab_app.py:624-640`), накапливаем в
   `read_errors` и показываем **все** разом одним диалогом, а не по одному.
4. **Tk-исключения при разрушении виджетов и геометрии глотаем:**
   `except tk.TclError: pass` (`graphlab_app.py:753-758`, `1011-1014`).
5. **Пользовательский ввод никогда не роняет приложение.** Целые из полей —
   только через `_to_int(v, default)` (`graphlab_app.py:577-582`); валидация
   обязательных полей — в `_prepare` с диалогом.
6. **Молча игнорируем только то, что не критично для запуска:** автосохранение
   (`_autosave`, `graphlab_app.py:1041-1049`), восстановление сессии
   (`_restore_state`), HiDPI-awareness в `main()`. Это единственные места
   с широким `except Exception: pass`; новые такие места — только с
   комментарием, объясняющим, почему молчание допустимо.
7. **CLI:** фатальная ошибка — `sys.exit("сообщение")` (один раз, в конце);
   проблемы отдельных файлов — предупреждение в stderr и продолжение
   (`graph.py:93-98`).

### Dirty-состояние

- Любое программное изменение полей (загрузка проекта, «Новый проект»)
  оборачивается `self._loading = True … finally: self._loading = False` —
  иначе загрузочные trace поставят ложную звёздочку.
- Потеря несохранённых изменений всегда через `_confirm_discard`
  (askyesnocancel: Да = сохранить, Нет = продолжить, Отмена = ничего).

## 3. Запреты

### Зависимости и сборка

1. **Не добавлять зависимости** кроме `tkinter`, `matplotlib`, `Pillow` —
   минимальный стек осознанное решение (ARCHITECTURE.md §6.1), он упрощает
   onedir-сборку.
2. **Не менять бэкенд matplotlib** с `Agg` на оконный — приложение
   портативное, работает и в CI.
3. **Не создавать временные папки при запуске** (`runtime_tmpdir=None` в
   spec); exe должен оставаться полностью внутри `dist\GraphLab\`.
4. Не включать `console=True` в GUI-сборку; CLI-вывод app не нужен.

### Структура

5. **Не распылять `graphlab_app.py` на пакет** без явного решения —
   однофайловость упрощает сборку и перенос (ARCHITECTURE.md §6.1).
6. **Не выносить парсер `.dat` в общий модуль** «по пути» — дублирование
   `graph.py`/`graphlab_app.py` зафиксировано как решение
   (`REVIEW_TZ.md`, «Не в скопе»); менять только по отдельному решению.
7. **Не менять формат `.gslab` v1** (ключи, относительные пути внутри папки
   проекта) без повышения `version` и обновления README/ARCHITECTURE.

### Поведение приложения

8. **«Построить график» не пишет на диск.** Рендер предпросмотра — только
   в `io.BytesIO`; PNG на диск создаёт исключительно «Экспорт в PNG».
9. **Не писать файлы в CWD при запуске** и не создавать папок без явного
   действия пользователя (`os.makedirs` — только в `export_png`); служебные
   файлы — только `%APPDATA%\GraphLab`.
10. **Не ронять подтверждение потери изменений** (`_confirm_discard`) при
    «Новый проект», «Открыть…» и закрытии окна.
11. **Не ломать раскладка-независимость хоткеев:** механизм трёх уровней
    (keysym-таблицы англ.+ЙЦУКЕН → Unicode `U0442` → физические VK-коды)
    менять только с сохранением всех трёх уровней.

### Стиль и ошибки

12. **Не использовать `print()` в GUI** — только статус-строка
    (`_set_status`) и диалоги; в CLI — только `graph.py`.
13. **Не ловить «голые» `except:`** — всегда конкретные исключения
    (`OSError`, `tk.TclError`, `(ValueError, TypeError)`…).
14. **Не добавлять молчающих `except Exception: pass`** вне §2.6 (автосохранение,
    восстановление сессии, HiDPI) — каждое такое место должно быть
    обосновано комментарием.
15. **Не создавать виджеты в обход фабрик** `_entry/_btn/_muted_label/_card`
    — теряется тема и контекстное меню ПКМ.
16. **Не хардкодить цвета/шрифты** в коде виджетов — только `T` и
    `F_BODY/F_SMALL/F_HEAD`.

### Репозиторий

17. Не коммитить `env/`, `build/`, `dist/`, `__pycache__/`, `*.exe`
    (уже в `.gitignore`) и не менять `.gitignore` в сторону их включения.
18. **Не оставлять устаревшие ссылки** в ARCHITECTURE.md: сдвиг строк —
    обновить документ в том же коммите.
