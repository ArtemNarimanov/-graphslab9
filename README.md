# graphslab9

Инструменты для построения графиков по данным GraphLab (`.dat`-файлы):
портативное GUI-приложение и CLI-скрипт. На выходе — готовые PNG;
GUI показывает окно Python-кода, CLI печатает строки для Markdown.

## Портативное приложение (v1.0.5)

`dist\GraphLab\` — портативная папка (onedir-сборка PyInstaller):
запустить `dist\GraphLab\GraphLab.exe` двойным кликом, установка не нужна.
Временные папки при запуске не создаются вообще.

Возможности:

- выбор `.dat` файла оси X и линий Y из проводника (несколько файлов сразу);
- цвет каждой линии: палитра по умолчанию + произвольный выбор цвета;
- подписи легенды — редактируемые, подставляются автоматически из имени файла;
- у каждой линии своё поле «строка начала Y» (по умолчанию 4);
- режим «Все линии на одном графике» — объединённый PNG с общей легендой;
- названия осей и графика;
- две кнопки вверху: **«Построить график»** (предпросмотр в памяти, на диск
  ничего не записывается) и **«Экспорт в PNG»** (те же графики — в папку);
- предпросмотр всегда вписан в окно (без апскейла), без ползунков;
- бокс «ДАННЫЕ» — постоянная белая карточка-рамка от верхнего края бокса до
  строки кнопки (не двигается и не растёт вместе с контентом, нижняя граница
  фиксирована); внутри неё прокручивается только контент (canvas внутри
  карточки), авто-скроллбар появляется, когда контент не помещается, и
  стоит на 12 px внутрь от правого края карточки; кнопка «+ Добавить линию» —
  в постоянной нижней строке бокса (не прокручивается, не двигается при смене
  режима); карточки «График» и «Вывод» статичны; правые края всех трёх левых
  боксов выровнены в обоих режимах скролла, зазор между панелями — 24 px;
- колесико мыши над панелью данных и Python-кодом: вниз — вниз, вверх — вверх;
- окно **Python-кода** — самодостаточный сниппет matplotlib (создаётся по
  «Построить график»), кнопка **«Скопировать код»**;
- сохранение проектов в файлы `.gslab` (см. ниже).

Окно при старте — 1450×815, минимальный размер 1024×576. Геометрия окна на диск не сохраняется (ни `config.json`, ни ключ `geometry` в `.gslab`) — окно всегда стартует 1450×815; если старый файл содержит геометрию, она игнорируется.

Результат: для каждого Y-файла создаётся PNG (имя — как у файла), а при
объединённом режиме — один файл с заданным именем. Окно **Python-кода**
показывает самодостаточный скрипт matplotlib, который рисует те же графики
и при запуске сохраняет их в папку `plots/`; статус показывает
«Предпросмотр: N график(ов), файлы не записаны» или «Экспорт: N PNG в …».

## Проекты `.gslab` и сохранение (v1.0.5)

Меню «Файл»:

- **Новый проект** (`Ctrl+N`) — сброс к состоянию по умолчанию;
- **Открыть проект…** (`Ctrl+O`) — загрузка `.gslab`;
- **Сохранить** (`Ctrl+S`) — в текущий файл, а если файл ещё не выбран —
  диалог «Сохранить как…»;
- **Сохранить как…** (`Ctrl+Shift+S`) — выбор имени файла `.gslab`.

Формат `.gslab` (JSON, версия 1) хранит все поля: X, линии (файл/числа Y,
легенда, строка начала, цвет, свой X), названия осей и графика, режим «все на одном»,
папку вывода. Пути записываются
относительно папки проекта — проект можно переносить вместе с данными.
Ключи `fit_preview` и `geometry` не пишутся; старые файлы с этими ключами
загружаются терпимо (ключи игнорируются).

Заголовок окна показывает имя проекта: `Новый проект` или имя файла без
расширения; несохранённые изменения помечаются звёздочкой
(`эксперимент* — GraphLab`). При открытии, новом проекте и закрытии
окна с несохранёнными изменениями спрашивается подтверждение:
**Да** — сохранить, **Нет** — продолжить без сохранения,
**Отмена** — ничего не делать.

При запуске последнее автосохранение (`last.gslab` в `%APPDATA%\GraphLab`)
загружается как «Новый проект»: данные восстанавливаются, но файл проекта
не считается открытым — `Ctrl+S` предложит выбрать имя.

## Горячие клавиши (v1.0.5)

| Клавиша | Действие |
| --- | --- |
| `Ctrl+N` | Новый проект |
| `Ctrl+O` | Открыть проект… |
| `Ctrl+S` | Сохранить |
| `Ctrl+Shift+S` | Сохранить как… |
| `Ctrl+X` | Вырезать выделенный текст |
| `Ctrl+C` | Копировать |
| `Ctrl+V` | Вставить |
| `Ctrl+A` | Выделить всё |

Текстовые сочетания работают в любом поле ввода (включая окно Python-кода).

## Сборка из исходника

### 1. Иконка (уже в репозитории)

`make_icon.py` генерирует `GraphLab.ico` (Pillow, есть в venv):

```
env\Scripts\python.exe make_icon.py
```

Иконка зашита в exe через `icon='GraphLab.ico'` в спеке и используется
установщиком.

### 2. Портативная версия (onedir)

`graphlab_app.py` — onedir, спецификация `GraphLab_onedir.spec`:

```
env\Scripts\pyinstaller.exe GraphLab_onedir.spec --noconfirm
```

Результат — папка `dist\GraphLab\` (`GraphLab.exe` + `_internal\`), её и
раздавать/запускать. Временные папки при запуске не создаются.

### 3. Установщик (Inno Setup)

`installer.iss` упаковывает onedir-бандл в setup-файл:

```
"C:\Program Files\Inno Setup 7\ISCC.exe" installer.iss
```

(если Inno Setup не установлен — поставить из `tools\innosetup-7.1.1-x64.exe`).

Результат — `out\GraphLab-Setup-1.0.5.exe`: русский мастер, установка в
Program Files (x64), опциональный ярлык на рабочем столе, запуск после
установки; данные пользователя (`%APPDATA%\GraphLab`) при удалении не трогаются.

Артефакты сборки (`dist/`, `build/`, `out/`) — в gitignore, в репозиторий
не попадают.

## CLI-скрипт

`graph.py` — та же логика без GUI. Требуется Python с matplotlib
(в папке `env/` уже есть venv):

```
env\Scripts\python.exe graph.py
```

Можно передать свои файлы:

```
env\Scripts\python.exe graph.py x.dat result_tav.dat result_tw1.dat
```

Для каждого Y-файла создаётся PNG (имя — как у файла) и на stdout печатается
строка для Markdown. Настройки (имена файлов, строка начала чтения Y) —
в начале `graph.py`.

## Формат данных

- `x.dat` — значения оси X, через `;` (или пробелы).
- `result_*.dat` — значения оси Y: первые 3 строки — заголовок и начальные
  значения (пропускаются), данные читаются с 4-й строки. Числа в экспоненциальной
  записи (`3.9211E+02`), разделители — пробелы/табы/точки с запятой, CRLF.
