**Проблема 1: нет прокрутки левой панели.**

  выталкивает «График»/«Вывод» за его пределы; **механизма прокрутки нет** —

**Проблема 2: нет колесика мыши.**

- Привязок `<MouseWheel>` в `graphlab_app.py` нет вовсе (проверено grep'ом;

## 2. ТЗ

### R6. Бегунок панели данных (левая колонка)

**Текущее состояние.** См. §1.3, проблема 1: высота левой колонки неограничена,
скролла нет.

**Требования.**

- **R6.1.** Сделать прокручиваемой **всю левую колонку** (все три карточки, а не
  только «Данные» — при большом числе линий «График»/«Вывод» должны оставаться
  достижимыми). Заменить содержимое `left` на контейнер:
  - `canvas = tk.Canvas(left, bg=T["bg"], highlightthickness=0)` — grid
    row 0, column 0, sticky="nsew";
  - `vbar = ttk.Scrollbar(left, orient="vertical", command=canvas.yview)` — grid
    row 0, column 1, sticky="ns";
  - `canvas.configure(yscrollcommand=vbar.set)`;
  - внутренний фрейм `inner = tk.Frame(canvas, bg=T["bg"])`, подвешенный через
    `win_id = canvas.create_window(0, 0, anchor="nw", window=inner)`; три
    карточки переносятся в `inner` (grid-строки 0/1/2 как сейчас).
- **R6.2.** Автоизмерение:
  - `<Configure>` на `inner` → `canvas.configure(scrollregion=canvas.bbox("all"))`;
  - `<Configure>` на `canvas` →
    `canvas.itemconfigure(win_id, width=event.widget.winfo_width())` — карточки
    растягиваются на ширину панели (за вычетом бегунка); при изменении ширины
    окна ширина сохраняется.
- **R6.3.** Карточка «Данные» теряет `stretch=True` (естественная высота);
  в `inner` веса строк не задаются — высоту колонки определяет содержимое.
- **R6.4.** Автоскрытие бегунка (решение по §4, вопрос 3): бегунок скрыт, пока
  содержимое помещается в окно, и появляется при переполнении:
  - на `<Configure>` `inner` и `canvas`: `content_h = canvas.bbox("all")[3]`,
    `view_h = canvas.winfo_height()`; если `content_h <= view_h` →
    `vbar.grid_remove()`, иначе `vbar.grid(row=0, column=1, sticky="ns")`;
  - `canvas.grid_columnconfigure(0, weight=1)` — когда бегунок скрыт, карточки
    растягиваются на всю ширину панели (без щели справа); при показе бегунка
    ширина автоматически уменьшается на его толщину (обработка R6.2).
- **R6.5.** Атрибут `self.left` продолжает указывать на внешний контейнерный
  фрейм; других ссылок в коде нет — изменения вне `_build_ui` не требуются.

**Критерии приёмки R6.**

1. 8+ линий Y: все карточки достижимы вертикальным бегунком, ничего не
   обрезано.
2. Карточки растянуты на ширину панели; горизонтальное изменение размера окна
   сохраняет полную ширину (без щели справа).
3. Мало линий (содержимое помещается) — бегунок скрыт; раскладка визуально
   неотличима от v1.0.3.
4. Добавление/удаление линии обновляет область прокрутки и видимость бегунка:
   при переполнении появляется, когда содержимое помещается — скрывается.

### R7. Колесико мыши в окнах графика и данных

**Текущее состояние.** Привязок `<MouseWheel>` нет; у вкладок предпросмотра есть
скроллбары, но не колесико; левая панель до R6 не прокручивается вовсе.

**Требования.**

- **R7.1.** Единый центральный обработчик `_on_mousewheel(e)`, привязанный через
  `root.bind_all("<MouseWheel>", self._on_mousewheel)`. `bind_all` покрывает
  динамически создаваемые виджеты (новые линии, новые вкладки предпросмотра) —
  повторная привязка в `add_line`/`_show_preview` не нужна.
- **R7.2.** Обработчик определяет область под указателем:
  `w = root.winfo_containing(e.x_root, e.y_root)`; обход цепочки `w.master`
  (включая сам `w`):
  - в цепочке есть canvas левой панели (R6) → `left_canvas.yview_scroll(steps, "units")`;
  - в цепочке есть canvas одной из вкладок предпросмотра
    (`_preview_tabs[*]["canvas"]`) → её `yview_scroll(steps, "units")`;
  - в цепочке есть поле кода `code_text` (R8) →
    `code_text.yview_scroll(steps, "units")`;
  - в ином случае — без действия (по умолчанию).
- **R7.3.** Шаги: Windows шлёт `e.delta = ±120` за щелчок;
  `steps = e.delta // 120`. Для высокоточных мышей (`|delta| < 120`) — скролл в
  сторону `sign(e.delta)`, минимум 1 unit. При обработанной области вернуть
  `"break"`, чтобы событие не ушло другим привязкам.
- **R7.4.** Режим «Вписывать в окно»: у canvas предпросмотра нет scrollregion
  (`_update_preview_for`, `graphlab_app.py:799-800`) — колесико там no-op без
  ошибок; левая панель прокручивается как обычно.
- **R7.5.** Shift+колесо → горизонтальный скролл canvas предпросмотра
  (`xview_scroll(steps, "units")`) (решение по §4, вопрос 2). Срабатывает только
  над вкладкой графика; в режиме «Вписывать в окно» — no-op (нет scrollregion).

**Критерии приёмки R7.**

1. Указатель над панелью данных (включая поля/кнопки внутри неё): колесико
   прокручивает панель вверх/вниз.
2. Указатель над вкладкой графика: колесико прокручивает изображение по
   вертикали; бегунок синхронно смещается.
3. Колесико над полем Python-кода прокручивает код по вертикали; над верхней
   панелью и остальными областями — без прокрутки и без ошибок.
4. Shift+колесо над вкладкой графика прокручивает изображение по горизонтали
   (бегунок синхронно смещается).
5. Добавление новых линий/вкладок не ломает колесико (без перепривязки).

### R8. Окно Python-кода для Jupyter вместо Markdown

**Текущее состояние.** Правая панель, карточка Markdown
(`md = tk.Frame(right, ...)`, `graphlab_app.py:534-549`): поле
`self.md_text` (`tk.Text`, height=4) с готовыми строками вида
`![caption](name.png)` (заполняется в `_update_md`,
`graphlab_app.py:690-692`; генерация строк — `preview_graph`
`graphlab_app.py:710,711` и `export_png` `graphlab_app.py:743,744`). Кнопки:
«Копировать в буфер» (`_copy_md`, `graphlab_app.py:809`) и «Открыть папку»
(`_open_outdir`).

**Требования.**

- **R8.1.** Заменить карточку Markdown на карточку «Python-код»: то же место
  (правая панель, row 2), поле `self.code_text` (`tk.Text`, read-only:
  `state=DISABLED`; при обновлении — временно `NORMAL`, delete/insert, затем
  снова `DISABLED`), высота ~8–10 строк, `wrap="none"`. К полю — вертикальный
  скроллбар `code_vbar` (`ttk.Scrollbar`,
  `code_text.configure(yscrollcommand=code_vbar.set)`) для обратной связи и
  прокрутки колесиком (R7.2). Кнопка «Копировать в буфер» → «Скопировать код»
  (`_copy_code`: копирует текст `code_text`); кнопка «Открыть папку» остаётся
  (открывает `out_dir`).
- **R8.2.** Новый метод `_build_snippet(self, prepared) -> str`, где
  `prepared` — тот же список `(xs, ys, color, label)`, что передаётся в
  `_build_figs` (`graphlab_app.py:659-688`). Сниппет строится из данных и
  параметров (title/xlabel/ylabel/combined), без создания matplotlib-фигур.
- **R8.3.** Сниппет — самодостаточный Python-код для Jupyter, который:
  - встраивает данные напрямую списками (`x1 = [...]`, `y1 = [...]`, …) —
    ссылок на `.dat` и пути приложения нет; числа — через `repr(float)`
    (короткая запись с точным round-trip);
  - воспроизводит тот же график: `figsize=(9, 5)`, `dpi=150`,
    `linewidth=2`, цвета из `prepared`, подписи легенды, title/xlabel/ylabel,
    стиль `_style_ax` (`graphlab_app.py:98-103`: скрыты верхняя/правая рамки,
    сетка `"--"` alpha 0.4, `legend(framealpha=0.9)`), `tight_layout(pad=0.4)`;
  - объединённый режим — одна фигура со всеми линиями; раздельный — по фигуре
    на линию (как в `_build_figs`);
  - сохраняет каждый график: `os.makedirs("plots", exist_ok=True)` +
    `fig.savefig(os.path.join("plots", "<имя>.png"), dpi=150,
    bbox_inches="tight")` — `<имя>` то же `safe_name(...)`, что в
    `_build_figs`; папка `plots` — относительная (рядом с notebook);
  - показывает график: `plt.show()` (в Jupyter рендерится inline).
- **R8.4.** Генерация при «Построить график»: в `preview_graph` вызвать
  `self._update_code(self._build_snippet(prepared))` вместо
  `self._update_md(md_lines)`; строки Markdown больше не формируются.
  При «Экспорт в PNG» код-поле не перезаписывается (сниппет от `out_dir`
  не зависит — см. §4, вопрос 5).
- **R8.5.** Переименование `self.md_text` → `self.code_text`; все точки
  использования: создание/grid/`_reg` (`graphlab_app.py:539-544`),
  `_update_md` → `_update_code`, `_copy_md` → `_copy_code`
  (`graphlab_app.py:809`), сброс при «Новый проект» (`graphlab_app.py:894`).

**Пример результата** (объединённый режим, 2 линии):

```python
import os
import matplotlib.pyplot as plt

# Данные (встроены из GraphLab)
x1 = [0.0, 1.0, 2.0]
y1 = [1.0, 4.0, 9.0]
x2 = [0.0, 1.0, 2.0]
y2 = [2.0, 8.0, 18.0]

fig, ax = plt.subplots(figsize=(9, 5), dpi=150)
ax.plot(x1, y1, color="#4682b4", linewidth=2, label="линия 1")
ax.plot(x2, y2, color="#e07b39", linewidth=2, label="линия 2")
ax.set_title("График")
ax.set_xlabel("X")
ax.set_ylabel("Y")
ax.spines["top"].set_visible(False)
ax.spines["right"].set_visible(False)
ax.grid(True, linestyle="--", alpha=0.4)
ax.legend(framealpha=0.9)
fig.tight_layout(pad=0.4)

os.makedirs("plots", exist_ok=True)
fig.savefig(os.path.join("plots", "combined.png"), dpi=150, bbox_inches="tight")
plt.show()
```

**Критерии приёмки R8.**

1. После «Построить график» в карточке — валидный Python-код; кнопка
   «Скопировать код» кладёт его в буфер целиком.
2. Вставленный в Jupyter и запущенный сниппет показывает тот же график, что
   предпросмотр приложения (заголовок, оси, цвета, сетка, легенда).
3. При запуске в Jupyter создаётся папка `plots` рядом с notebook и
   сохраняются PNG с теми же именами, что у «Экспорт в PNG».
4. Сниппет не содержит ссылок на `.dat`, пути приложения или внешних файлов —
   работает в чистом окружении с установленным matplotlib.
5. Раздельный режим: по одной фигуре и одному PNG на линию.

1. Колесико для поля Python-кода — **да**: R7.2 добавляет область `code_text`,
   R8.1 даёт полю вертикальный скроллбар.
2. Shift+колесо → горизонтальный скролл графика — **да**: R7.5 обязательный.

   при «Построить график» (R8.4 без изменений).

   (`x1..xn`, всегда корректно); оптимизацию можно рассмотреть позже.
