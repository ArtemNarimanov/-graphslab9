- **`_build_menu` (250–288)** — меню «Файл»: «Открыть проект…» / «Сохранить проект…» / «Выйти»;меню «Правка» через виртуальные события `<<Cut>>/<<Copy>>/<<Paste>>/<<SelectAll>>`;`root.bind_all("<Control-KeyPress-x/c/v/a>") → _focus_event` (269–272); контекстное меню ПКМ.

Tk на Windows нативно НЕ мапит Ctrl+C/V/X/A(`tk8.6/entry.tcl` стр. 205: `bind Entry <Control-Key> {# nothing}`) — событиеперегенерируется на виджете с фокусом и ловится его классовыми связями (Entry/Text).
- **`_build_ui` (322–433)** — левые карточки Данные/График/Вывод; верхняя панель справа:`gen_btn` «  Построить графики  » (стр. 389, `command=self.generate`) + статус;предпросмотр `ttk.Notebook`; поле Markdown `tk.Text` + «Копировать в буфер» / «Открыть папку».
- **`generate()` (467–562)** — валидация строк → список `prepared` → разрешение `out_dir`(явная папка, иначе каталог основного X, иначе каталог приложения; 511–515) →**`fig.savefig(path)` на диск по каждому графику** (534, 549) → строки Markdown →`_show_preview(png_paths)` → статус «Сохранено: N PNG в …».
- **`_show_preview` (565–595)** — вкладка на каждый PNG; **изображение читается с диска**(`Image.open(path)`, стр. 576); canvas + вертикальная/горизонтальная прокрутка;«вписать в окно» через `_update_preview_for` (597–612).
- **Проекты `.gslab`:** `save_project` (635–674) — JSON v1, пути внутри папки проекта —относительные; `load_project` (676–687); `load_project_from_dict` (689–734);`_project_resolves` (736–757).
- **Автосохранение:** `_autosave` (760–768) → `%APPDATA%\GraphLab\config.json` + `last.gslab`;`_restore_state` (770–800) — геометрия из config.json, `last.gslab` молча, если пути резолвятся.
- **`_on_close` (802–804)** — `_autosave()` + destroy, **без запроса о несохранённых изменениях**.
- **Меню проектов:** `_menu_save_project` (807–817) — всегда диалог «Сохранить как»(`asksaveasfilename`); `_menu_open_project` (819–825).

### 1.3 Сильные стороны

- Один файл GUI, минимальные зависимости (matplotlib + Pillow), понятная структура.
- Формат проекта — простой JSON v1 с относительными путями: переносимый, человекочитаемый.
- Чтение данных гибкое: файлы или числа inline, разделители `;`/пробелы, E-запись, CRLF.
- Предпросмотр в вкладках с прокруткой и «вписать в окно»; Markdown-строки для отчёта.
- Документированная onedir-сборка PyInstaller.

### 1.4 Проблемы (непосредственно по запросу)

1. **`generate()` смешивает предпросмотр и запись на диск**: каждое нажатие«Построить графики» сразу пишет PNG в `out_dir` (стр. 534, 549). Нужен разрыв:предпросмотр — без файлов, экспорт — отдельной кнопкой.
2. **Предпросмотр строится с диска** (`_show_preview`, `Image.open(path)`, стр. 576) —после разделения предпросмотр должен рендериться в памяти (BytesIO).
3. **Нет понятия «текущий проект»**: `_menu_save_project` всегда открывает диалог выборафайла; нет «Сохранить» в открытый файл, нет состояния «изменён/не изменён».
4. **Статичный заголовок окна** (стр. 193) — не показывает имя проекта и несохранённые изменения.
5. **Горячие клавиши**: связаны только `Ctrl+X/C/V/A` строчные (269–272). Механизм сам по себерабочий и охватывает все Entry/Text, но набор неполный («и так далее» из запроса),ускорители не подписаны в меню.
6. **Закрытие без подтверждения** несохранённых изменений (802–804) — при новой системесохранения нужно стандартное «Сохранить / Не сохранять / Отмена».
7. **Нет действия «Новый проект»** — требуется, т.к. заголовок должен уметь показывать «Новый проект».
8. **`last.gslab` и новая система**: после восстановления сессии из `last.gslab` заголовок недолжен выводить «last» — восстановленное состояние следует считать «Новым проектом»с загруженным содержимым (решение R1.10).


Не в скопе: дублирование логики чтения данных между `graph.py` и `graphlab_app.py`(можно вынести в общий модуль позже), формат `.gslab` v1, spec-файл PyInstaller.

## 2. ТЗ

### R1. Тонкая система сохранения

**Текущее состояние.** Единственное сохранение — «Сохранить проект…» с диалогом выборафайла каждый раз (`_menu_save_project`, 807–817). Состояний «текущий файл» и «изменён» нет.

**Требования.**

- **R1.1.** Ввести состояние проекта в `App`:- `self.project_path: str | None` — путь открытого/сохранённого `.gslab`; `None` = «Новый проект»;
- `self._dirty: bool` — есть ли несохранённые изменения.
- **R1.2.** Отметка «изменён» (`_mark_dirty()`) при любомпользовательском изменении:
- переменные приложения: `x_file, title_var, xlabel_var, ylabel_var, out_dir, combined, combined_name, fit_preview` — через `trace_add("write", ...)`;
- поля каждой `YLine`: `path_var, legend_var, start_var, x_path_var, x_start_var`(аналогично trace) и `_pick_color`;
- структурные действия: `add_line`, удаление линии (`_remove`).
- **R1.3.** Меню «Файл» (порядок): «Новый проект» (Ctrl+N), «Открыть проект…» (Ctrl+O),«Сохранить» (Ctrl+S), «Сохранить как…» (Ctrl+Shift+S), «Выйти». Ускорители подписать в меню(`accelerator=...`) и связать через `root.bind_all`.
- **R1.4.** «Сохранить»: если `project_path` задан — `save_project(project_path)` без диалога,`_dirty=False`, обновление заголовка; иначе — переход к диалогу «Сохранить как…» (R1.5).
- **R1.5.** «Сохранить как…»: `asksaveasfilename` (`*.gslab`) → `save_project(path)` →`project_path = abspath(path)` → `_dirty=False` → обновление заголовка.
- **R1.6.** «Открыть проект…»: если `_dirty` — подтверждение (R1.8); после успешного`load_project`: `project_path = abspath(path)`, `_dirty=False`, обновление заголовка.
- **R1.7.** «Новый проект»: если `_dirty` — подтверждение (R1.8); сброс к состоянию по умолчанию:одна пустая линия, значения переменных по умолчанию, `project_path=None`, `_dirty=False`,очистка вкладок предпросмотра и поля Markdown.
- **R1.8.** Диалог подтверждения несохранённых изменений (`askyesnocancel`):Да — сохранить (в текущий файл или через «Сохранить как…»), Нет — продолжить без сохранения,Отмена — ничего не делать. Используется при открытии проекта, создании нового и закрытии окна.
- **R1.9.** Закрытие окна: если `_dirty` — подтверждение (R1.8); затем текущее `_autosave()` +`destroy()` (автосохранение оставляем для восстановления сессии).
- **R1.10.** Восстановление при запуске (`_restore_state`): содержимое `last.gslab` загружается,но `project_path` остаётся `None`, `_dirty=False` — состояние трактуется как «Новый проект»с данными; Ctrl+S откроет «Сохранить как…», заголовок — «Новый проект».

**Критерии приёмки R1.**

1. Старт → заголовок «Новый проект»; ввод в любое поле → «Новый проект\*».
2. Ctrl+S без открытого файла → диалог выбора; сохранено как `t.gslab` → заголовок «t» (без \*).
3. Изменение поля → «t\*»; Ctrl+S → запись в тот же файл **без** диалога → «t».
4. Открытие другого проекта при наличии изменений → диалог Да/Нет/Отмена; «Да» сохраняет текущий,«Нет» отбрасывает, «Отмена» ничего не меняет.
5. То же поведение при «Новый проект» и закрытии окна.

### R3. Предпросмотр и экспорт раздельно

**Текущее состояние.** Кнопка «Построить графики» (стр. 389) → `generate()` пишет PNG на диски показывает их в вкладках; статуса «предпросмотр» не существует.

**Требования.**

- **R3.1.** Кнопку переименовать: «Построить графики» → **«Построить график»**,`command=preview_graph`. Рядом добавить кнопку **«Экспорт в PNG»** (`command=export_png`).
- **R3.2.** Выделить из `generate()` общий метод `_prepare()`: текущая валидация и сборкасписка `(xs, ys, color, legend)` + warnings (469–509) без изменений; при ошибке —`showerror` и `None`.
- **R3.3.** Построение фигур (combined / по линиям, 523–552) — общий код обоих кнопок.Для предпросмотра рендер в память:`buf = io.BytesIO(); fig.savefig(buf, format="png", dpi=150, bbox_inches="tight"); buf.seek(0); img = Image.open(buf)` — **никаких записей на диск**.
- **R3.4.** `preview_graph()`: `_prepare()` → рендер в память → обновление `md_text` (те жестроки Markdown, что сейчас) → `_show_preview(изображения)` → статус«Предпросмотр: N график(ов), файлы не записаны» (с префиксом ⚠ при warnings).
- **R3.5.** `export_png()`: `_prepare()` → разрешение `out_dir` и запись PNG на диск(текущая логика 511–515, 534/549) → `md_text` → предпросмотр тех же изображений →статус «Экспорт: N PNG в {out_dir}».
- **R3.6.** `_show_preview` (565–595) изменить на приём списка PIL-изображений (+имён вкладок)вместо путей: убрать `os.path.isfile` и `Image.open(path)`; прокрутка и «вписать в окно»сохраняются без изменений.

**Критерии приёмки R3.**

1. «Построить график» → вкладки предпросмотра появились, **в `out_dir` новых файлов нет**.
2. «Экспорт в PNG» → ровно N файлов созданы в `out_dir`, статус с путём.
3. Текст Markdown одинаков для обоих кнопок.
4. Ошибки данных (нет файла / не целое «с:») — те же диалоги, что сейчас.


### R4. Горячие клавиши во всех полях

**Текущее состояние.** `root.bind_all("<Control-KeyPress-x/c/v/a>") → _focus_event`(269–272), который перегенерирует событие на виджете с фокусом (281–284, есть guard от `None`).Работает для всех `tk.Entry`/`tk.Text`, т.к. Tk на Windows нативно эти клавиши не мапит(`entry.tcl:205`). Механизм **сохраняется**, а не заменяется.

**Требования.**

- **R4.1.** Сохранить механизм `bind_all + event_generate`; охват — все поля: файл X,по каждой линии (Y, легенда, «Y с:», X, «X с:»), название, подписи осей, папка PNG,имя объединённого, поле Markdown. Все они — Entry/Text, созданные через `_entry`/`_reg`,отдельных отключений нет — достаточно проверить каждое поле вручную.
- **R4.2.** Расширить набор клавиш: `x, c, v, a` (текущие) + опционально `z, y`(undo/redo для `md_text`, при создании `tk.Text(..., undo=True)`). Ядро — x/c/v/a;z/y — по желанию заказчика.
- **R4.3.** Подписать ускорители в меню «Правка» (`accelerator="Ctrl+C"` и т.п.);пункты меню продолжают вызывать те же виртуальные события.
- **R4.4.** Контекстное меню ПКМ (275–288) и guard от `None` в `_focus_event` не менять.

**Критерии приёмки R4.** В каждом поле: Ctrl+A — выделить всё, Ctrl+C — копия выделенногов буфер, Ctrl+X — вырезать, Ctrl+V — вставить; поведение идентично нативному (текст вбуфере обмена проверяется через `root.clipboard_get()`).
